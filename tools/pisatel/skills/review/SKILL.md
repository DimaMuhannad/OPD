# /review N — свежий читатель

Аргумент — `id` пункта из `progress.toml` (например, `/review 3.2`) или путь к файлу.

## Шаги

1. **Найти текст и опоры.** В `progress.toml`: у пункта `N` поле `fail` — текст; `[nastrojki]`:
   `pravila`, `chitatel`, `proverki`, `briefy` (задание `<briefy>/<N>.md`, если есть).
2. **Автопроверки.** Запустить команды из `proverki`. Их ошибки — первые замечания; агенту передать
   вывод, чтобы он не тратил силы на то же самое.
3. **Свежий читатель.** Запустить агента `svezhiy-chitatel` (плагин pisatel) и передать ему в задании
   **пути** (не содержимое): текст, задание, файлы правил, описание читателя и вывод автопроверок.
   Агент только читает. Если агентов в среде нет — выполнить ту же проверку самому по инструкции
   из `<папка плагина>/agents/svezhiy-chitatel.md`, не перечитывая собственный черновик «глазами автора».
4. **Сохранить отчёт** в `<briefy>/<N>-review.md`: замечания агента как есть, у каждого поле решения
   `[ ]` (позже `[принято]`, `[отклонено]`, `[исправлено]`); в `progress.toml` — `etap = "review: отчёт готов, ждёт решений"`.
   Если такой отчёт уже есть и в нём остались нерешённые замечания — **продолжить с него**,
   агента заново не запускать (это и есть возврат после `/clear`).
5. **Показать автору** замечания сгруппированные «обязательно / желательно / можно»,
   и строку о критериях задания. Спросить опросником (AskUserQuestion), что исправлять: все
   обязательные, выбранные, ничего.
6. **Исправить только одобренное**, отмечая в отчёте решение у каждого замечания; снова запустить автопроверки. Если в проекте есть сборка
   (навык проекта, например `/glava`) — пересобрать и посмотреть результат.
7. **Прогресс.** Статус меняет автор: после вычитки и показа — `vychitka`; `odobreno` — только по его «да».
   Убрать `etap`, записать в `progress.toml`, запустить `/progress`, коммит (вместе с отчётом).

## Чего не делать

- Не отдавать агенту право писать файлы и не просить его переписать текст.
- Не исправлять «можно»-замечания без просьбы автора.
