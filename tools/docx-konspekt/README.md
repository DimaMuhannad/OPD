# Печатный docx-двойник конспекта / справочника

Источник — `.md` в `zanyatiya/`, правки вносятся туда; скрипты здесь
собирают из него печатную чёрно-белую версию в `.docx` через npm-пакет
`docx` (`npm install docx@9` в рабочей папке с `node_modules`, например
в scratchpad сессии).

Правило: содержание (текст, таблицы) копируется из актуального `.md`
вручную в скрипт при сборке или обновлении — скрипт не парсит Markdown
автоматически. При правке `.md` соответствующий блок в скрипте поправить
тем же изменением, не давать им разойтись.

Цвета — без раскраски: чёрный текст (`#1A1A1A`), бледно-серая заливка
(`#E8E8E8`) для шапок таблиц и колл-аутов «Пример»/«Определение», серые
линии (`#999999`) вместо акцентного синего под заголовками. Та же логика,
что в чёрно-белом `Zanyatie_04_Pasport_Blank.docx`.

`build_Zanyatie_04_Konspekt.js` — конспект занятия 4 собран в жанре
**справочника** (см. `CLAUDE.md`, уточнение от 26.09.2026): без
хронометража, цикла разбора и прочей режиссуры пары — только раздел,
определение/пример, типичная ошибка и критерии оценки. Пример открыт
(не помечен «не показывать студентам») — документ адресован в том числе
студентам. Если следующая практика собирается как методичка для
преподавателя (жанр по умолчанию, см. `Zanyatie_03_Praktika2_Pasport_Konspekt.docx`),
хронометраж и ориентиры «только для преподавателя» возвращаются.

Проверка перед сдачей: `zipfile` + `xml.dom.minidom.parseString` на
`word/document.xml` (LibreOffice файлы от `docx`-пакета не открывает —
известное ограничение, см. `CLAUDE.md`), и сверка текста построчно
с исходным `.md`.
